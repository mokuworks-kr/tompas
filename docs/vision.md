# 비전

TOMPAS는 디자이너의 선택을 대신하지 않고, 선택의 비용을 낮추는 편집 디자인 보조 도구다. 회사소개서·보고서·제안서처럼 20쪽이 넘는 인쇄물을 InDesign에서 만든다.

## 무엇을 누가 하나

- 도구: 답이 하나로 정해지는 일. 원고 읽기, 사실 잠금, 격자 계산, 넘친 글 맞추기, 줄바꿈, 규칙 검사.
- 디자이너: 답이 여럿이고 고르는 것이 곧 디자인인 일. 무엇이 주인공인가, 서체, 색, 사진을 어디에.
- 함께: 선택지를 펼치는 일(후보를 나란히 조판, 스케치를 받아 변주). 디자이너가 청할 때 펼치고, 고르는 것은 디자이너다.

경계는 "AI가 못 하는 일"이 아니라 "디자이너가 계속 손으로 하고 싶은 선택"으로 긋는다. 앞의 것은 모델이 나올 때마다 밀린다(D-47).

에이전트는 단계마다 디자이너의 의도를 먼저 묻는다. 추천은 하나만, 약하게 한다. 써서 보여 준 선택지는 그것만으로 생각을 묶는다.

## 패스트 트랙

같은 엔진 위의 지름길이다. 모든 선택에서 에이전트의 추천을 그대로 받아, 원고 하나로 최종 InDesign 파일까지 간다. 시간에 쫓길 때 쓴다. 흔한 답을 받아들인다. 절차는 `tompas/fast.md`.

## 사용자

이 도구를 만드는 디자이너 자신. 저장소는 공개하지만 쓸 권리는 주지 않고, 팔지 않는다(D-44, D-47, D-50). Adobe 전체 앱, AI 구독, 로컬 에이전트(Claude Code, Codex)를 갖고 있다.

## 입력과 출력

- 입력: 원고(HWP, HWPX, DOCX, PDF 등. kordoc이 읽는다). 브랜드 가이드는 없다고 본다. 로고는 받으면 자리에 놓기만 한다.
- 출력: 디자이너가 그대로 이어 작업할 INDD. 재정의가 없고, 스타일 이름이 뜻을 말하고, 미세 조정을 막는 설정이 없다.

## 하지 않는 것

- 디자이너 몰래 취향을 정하기. 흑백 구조안에는 도구가 고른 서체·색·주인공이 없다.
- 사진 처리(보정, 누끼, 톤 통일).
- 웹앱, 서버, 유료 API.

## 잘 됐는지 보는 법

- 일반 트랙(V1 완성 조건, D-47): 디자이너가 되돌려야 할 결정이 하나도 없고, 직접 하면 지루하기만 한 일이 남지 않는다.
- 패스트 트랙: 디자이너가 마무리하는 데 드는 시간.

## 원칙

1. 고르는 것은 사람, 계산은 도구, 조판은 InDesign.
2. 도구 안에는 AI가 없다. 디자이너의 에이전트가 도구를 부른다.
3. 목록 대신 규칙. 규칙은 어긋남을 잡기만 하고 모양을 강제하지 않는다.
4. 구조 먼저(와이어프레임), 테마 나중.
5. 판단은 데이터 파일에 남고, 엔진은 계산만 한다. LLM은 데이터를 만들고 코드는 만들지 않는다.
6. 코어는 얇게. 필요해질 때까지 들이지 않는다.

## 용어

| 용어 | 뜻 |
|---|---|
| 와이어프레임 | 서체·색 없이 격자 영역, 색 역할, 텍스트 역할만 가진 쪽 구조. 아웃라인 모드처럼 보인다. |
| 와이어프레임 텍스트 | 와이어프레임을 글자 격자로 적는 표기(`tompas/references/wireframe.md`). |
| 페이지 맵 | 각 쪽에 어떤 와이어프레임과 원고가 놓이는지 정리한 표. |
| 테마 | 프로젝트마다 입히는 시각 값. 서체, 크기 척도, 색, 그래픽 언어. |
| 색 역할 | 바탕·글자·보조·강조. 밝은 쪽과 어두운 쪽 두 톤. |
| 규칙 | 편집 원리와 한글 조판 관습을 변수 사이의 관계로 적은 것. 번호가 공용어다(`tompas/references/rules.json`). |
| 구성 원리 | 디자이너가 쓰는 구성 방식. 언제 쓰고 언제 쓰지 않는지와 함께 적는다(아직 없음, D-42). |
| 클리셰 목록 | 흔한 조합. 막지 않고, 후보 셋 중 하나까지만 둔다. |
| 아카이브 | 규칙 수치를 잰 최고급 스튜디오 작업. 저장소에 올리지 않는다. |
| 테스트 원고 | 엔진·규칙·모델이 바뀔 때 돌려 보는 원고 묶음(`test/`). |
| 임시 규칙 | 모델의 약점을 메우는 규칙. 모델이 나아지면 지운다. |
